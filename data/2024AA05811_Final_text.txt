1. Broad Area of Work 
This dissertation sits at the intersection of Agentic AI, Natural Language Processing, and Multimodal 
Systems. The specific sub-areas addressed are: 
• 
Multi-agent system design using LangGraph — coordinating specialist and reflective agents 
for multi-step question answering tasks 
• 
Retrieval-Augmented Generation (RAG) — combining document retrieval with language 
model generation over domain-specific knowledge bases 
• 
Multimodal document processing — extracting information from scanned images such as soil 
health cards, medical prescriptions, and government certificates using Vision-Language 
Models 
• 
Automated evaluation — measuring answer faithfulness, context precision, and relevancy 
using the RAGAS framework on a curated multilingual benchmark 
• 
Multilingual NLP — enabling Hindi and English query handling through cross-lingual sentence 
embeddings 
• 
Explainable AI (XAI) and answer transparency — providing source attribution, retrieval 
evidence, and execution traces so that generated answers can be verified by end users 
 
2. Background 
Retrieval-Augmented Generation has become a widely used approach for knowledge-intensive 
question answering [Lewis et al., 2020; Gao et al., 2023]. By pairing a retrieval component over 
indexed documents with a generative language model, RAG systems can produce more factually 
grounded responses than pure generation. However, many implementations in the literature are 
single-domain: a system built for medical question answering is separate from one designed for legal 
document search, and neither supports agricultural advisory [Gao et al., 2023]. Maintaining three 
separate systems is costly, and none of them can answer questions that naturally span domains — for 
example, a farmer asking both about a crop disease and the government subsidy available for it. 
A second limitation is that many deployed RAG systems offer limited transparency. The user receives 
a generated answer but no indication of which source document it came from, how confident the 
system is, or what retrieval steps were taken. In domains like healthcare and legal services, this is a 
practical problem: users, auditors, and oversight bodies often need to verify a claim rather than simply 
accept it. Recent work on self-reflective RAG [Asai et al., 2024] and GraphRAG [Edge et al., 2024] has 
begun to address quality issues, but Explainable AI (XAI) — specifically source attribution, confidence 
scoring, and retrieval provenance — remains a gap in cross-domain RAG systems. 
Language coverage is another concern. India has over 140 million farming households, and a large 
share of rural users accessing government welfare schemes and agricultural advisories communicate 
primarily in Hindi. Almost all existing RAG deployments are English-only, which limits their usefulness 
for these populations. 
Finally, there is no automatic mechanism in standard RAG pipelines to detect and remediate low-
quality outputs before they reach the user. A system that can route a query to the right domain KB, 
retrieve relevant passages, generate an answer, and then evaluate its own output — re-querying if

the confidence is low — would address this gap. Work on self-RAG [Asai et al., 2024] and agent-based 
orchestration [Yao et al., 2023] provides the conceptual basis for this. 
This dissertation proposes TriSeva, a six-agent LangGraph system designed to address the above 
limitations. It handles queries across three domains — Healthcare, Legal/Government, and Agriculture 
— in both English and Hindi, produces source-attributed answers with execution traces and retrieval 
evidence, and uses a dedicated Critic Agent to check output quality before delivery. The Agriculture 
domain is chosen specifically because of its relevance to the Indian rural context and C-DAC Pune’s 
active AgriTech work. The system is evaluated on the TriSeva-QA benchmark using RAGAS metrics, 
with results expected to fall in the range of recently reported multilingual RAG baselines.

3. Objectives 
The objectives of this dissertation are as follows: 
• 
System design and implementation: Build a six-agent LangGraph system comprising a Domain 
Router, three domain Specialist Agents (Healthcare, Legal/Government, Agriculture), a 
Reflective Critic Agent, and a Memory Agent. The agents are connected via a typed StateGraph 
with conditional edge routing. 
• 
Domain routing: Fine-tune a DistilBERT classifier to route incoming queries to the correct 
domain knowledge base, with a user-override option. The target is greater than 90% 
classification accuracy on the TriSeva-QA evaluation set, in line with similar domain 
classification results in the literature. 
• 
Multimodal document processing: Integrate InternVL2-8B (4-bit quantized) to extract 
structured information from scanned documents — specifically soil health cards, medical 
prescriptions, and government certificates. Inference is run on Kaggle free-tier T4 GPU. 
• 
Cross-lingual retrieval: Build a ChromaDB vector store with LaBSE embeddings over 
approximately 45,000 document chunks, supporting both English and Hindi queries without 
separate language-specific pipelines. 
• 
Reflective evaluation loop: Implement a Critic Agent that checks each generated answer 
against its retrieved context using RAGAS Faithfulness as a heuristic signal. When the score 
falls below a configurable threshold, the agent triggers a re-query rather than passing the 
answer to the user. 
• 
Answer transparency (XAI): Surface the source document, chunk reference, and retrieval 
similarity score alongside every answer. Workflow traces and retrieval provenance logs are 
recorded via LangSmith and made accessible in the Chainlit UI — these are agent execution 
logs and retrieved context records, not internal model reasoning tokens. Out-of-scope queries 
are flagged explicitly rather than answered speculatively. 
• 
Evaluation: Measure Faithfulness, Context Precision, and Answer Relevancy on the TriSeva-
QA benchmark using RAGAS. Conduct ablation studies to isolate the contribution of the 
routing module (RQ1), the vision component (RQ2), and the Critic Agent (RQ3). Target scores 
are informed by RAGAS evaluations in recent literature and are treated as aspirational rather 
than guaranteed: Faithfulness approximately 0.75, Context Precision approximately 0.90, 
Answer Relevancy approximately 0.90. 
• 
Benchmark dataset: Curate and release TriSeva-QA, a multilingual QA dataset distributed 
across Healthcare, Legal/Government, and Agriculture. An initial annotated set of 
approximately 188 pairs (Healthcare ≈64, Legal/Government ≈62, Agriculture ≈62) in English 
and Hindi with easy/medium/hard difficulty labels will be compiled first; the full benchmark 
targets approximately 500 pairs by final submission. The dataset will be released on 
HuggingFace Datasets under CC-BY 4.0. 
• 
Deployment: Deploy the complete system as a publicly accessible Chainlit / Streamlit 
application on HuggingFace Spaces, with LangSmith execution traces available during the viva 
demonstration.

Illustrative Use Cases 
The following ten scenarios ground the above objectives in concrete user interactions. Use Cases 1–5 
represent core system functionality to be demonstrated at Mid-Semester Viva. Use Cases 6–10 cover 
multimodal, ablation, and cross-domain functionality for the Final Viva. 
 
Use Cases 1–5: Mid-Semester Viva 
• 
UC-1 — Drug interaction query (Healthcare): A patient’s family member submits a Hindi 
query asking whether two common medications can be taken together. The Healthcare 
Specialist retrieves the relevant MedlinePlus contraindication entry, the Critic evaluates the 
response, and the Chainlit UI shows the source chunk and retrieval confidence score alongside 
the answer. 
• 
UC-2 — Welfare scheme eligibility (Legal/Government): A citizen asks in English about land-
holding eligibility for PM-KISAN. The Legal Specialist retrieves the relevant criteria from the 
MyScheme.gov.in knowledge base and returns the answer with the source section reference. 
• 
UC-3 — Crop advisory (Agriculture): A farmer submits a Hindi query: ‘Meri gehun ki fasal mein 
pila rang aa raha hai, kya karna chahiye?’ (My wheat crop is yellowing — what should I do?). 
The Agriculture Specialist retrieves an ICAR advisory and returns a recommended course of 
action with the source document cited. 
• 
UC-4 — RTI timeline query (Legal/Government): A government officer asks about the 
response timeline under RTI Section 7. The Legal Specialist returns the clause-level answer 
from the India Code knowledge base with section number and chunk identifier visible in the 
transparency panel. 
• 
UC-5 — Cross-domain agricultural scheme query: A farmer asks in one message about PM-
KISAN income eligibility and which crops qualify for MSP. The Domain Router identifies this as 
a cross-domain request and invokes both the Legal/Government and Agriculture Specialists. 
The final answer presents both source chains. 
 
Use Cases 6–10: Final Viva 
• 
UC-6 — Soil Health Card OCR (Multimodal Agriculture): A farmer uploads a photograph of a 
Soil Health Card. InternVL2-8B extracts the nutrient readings (N, P, K, pH), and the Agriculture 
Specialist returns fertiliser recommendations based on those values, citing the relevant ICAR 
guidelines. 
• 
UC-7 — Scanned prescription query (Multimodal Healthcare): A user uploads a scanned 
prescription and asks whether any of the listed drugs are contraindicated. The vision module 
extracts the drug names; the Healthcare Specialist queries MedlinePlus and returns the result 
with extraction trace visible. 
• 
UC-8 — Critic Agent ablation (RQ3): The same query is answered with and without the Critic 
Agent active, and the RAGAS Faithfulness scores are shown side by side. This is the primary 
validation for RQ3, with an expected improvement of at least 0.05 in the Critic-active 
condition.

UC-9 — Agricultural scheme + land record verification (cross-domain multimodal): A farmer

4. Scope of Work 
The following work will be carried out independently as part of this dissertation: 
• 
Design and implementation of the six-agent LangGraph StateGraph, including the Domain 
Router, three Specialist Agents (Healthcare, Legal/Government, Agriculture), Reflective Critic 
Agent, and Memory Agent, with conditional edge routing and a re-query loop 
• 
Construction of three domain knowledge bases from publicly available sources: MedlinePlus 
and NHP India for Healthcare; MyScheme.gov.in and India Code for Legal/Government; ICAR 
crop advisories, Kisan Call Centre FAQs, PM-KISAN documents, and Soil Health Card guidelines 
for Agriculture. The combined KB is expected to contain approximately 45,000 text chunks 
indexed in ChromaDB with LaBSE embeddings 
• 
Fine-tuning of a DistilBERT classifier for domain routing across the three domains, with a 
classification accuracy target of greater than 90% on the evaluation set 
• 
Integration of InternVL2-8B (4-bit quantized, Kaggle T4 free tier) for processing scanned 
documents, with specific focus on Soil Health Card extraction and medical prescription OCR 
• 
Implementation of Explainable AI (XAI) and answer transparency features: source attribution 
with document chunk and page reference, per-response RAGAS Faithfulness scoring, 
execution trace logging via LangSmith, and out-of-scope query flagging 
• 
Curation of the TriSeva-QA dataset: an initial annotated set of approximately 188 QA pairs 
(Healthcare ≈64, Legal/Government ≈62, Agriculture ≈62) in English and Hindi, with 
easy/medium/hard difficulty splits, growing to a target of approximately 500 pairs by final 
submission. The dataset will include image-based queries for multimodal evaluation 
• 
Automated evaluation using RAGAS metrics on the TriSeva-QA benchmark, along with 
ablation experiments addressing RQ1 (routing contribution), RQ2 (vision module 
contribution), and RQ3 (Critic Agent contribution) 
• 
Deployment of the system as a publicly accessible Chainlit / Streamlit application on 
HuggingFace Spaces 
 
The following are explicitly outside the scope of this dissertation: fine-tuning of the core language 
model backbone; mobile application development; real-time data streams such as live mandi prices 
or weather feeds; and private enterprise deployment.

•
